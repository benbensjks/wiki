# RDF 承重性探针：设计（**预登记**，尚未实现、尚未运行）

写入时状态：本文只是设计。`check_rdf_collapse.py` 的现有 v1/v2 已被判定**不能回答该问题**
（理由见 §2、§3），下面的判据是在**任何探针代码写完之前**定下的。

---

## 1. 问题，以及三种事先写清的答案

"bit2 停滞是不是因为 RDF 池被自己的 Hill 抑制掏空"这个问题，只有三种结局，事先全部列出：

| 结局 | 含义 | 对报告的影响 |
|---|---|---|
| **A. 承重** | 把 bit2 的 RDF 池压到某个水平以下，计数**必然**失效，且失效阈值与"抑制非线性"的具体形状有关（不只是池的量） | 机制段可以写"崩塌是承重结构"；剂量扫描不再是正确的改进方向 |
| **B. 只是剂量** | 失效只取决于达到的池水平，与抑制曲线的形状无关 | 崩塌是**描述**而不是机制；改进方向回到剂量/时序 |
| **C. 不承重** | 把池压到接近 0，计数**仍然**成立 | 存储态不依赖该池；早先的停滞是剂量/时序问题，崩塌与停滞**无因果关系** |

三种结局都会**不改动**冻结工作点的计数结论（n=6 在冻结点是认证的）。本探针只影响报告的
**机制解释**章节。

## 2. 为什么 v1 作废

v1 直接全局 patch `ZENG['n_rep']` / `ZENG['K_rep']`。这两个是**上游振荡器与冻结两比特前缀也在用**
的共享槽位，改它们把冻结前缀一起改掉了：`reverse_events` 从 14 变成 **0**，
即前缀本身已经不工作，任何"恢复计数"的观测都失去意义。v1 的判决已撤回。
这是 H2 的又一个实例（同一个全局槽位被两处语义不同地使用）。

## 3. 为什么 v2 的判决**空洞**

v2 改成 bit2-only 的子类覆写（`Bit2RdfProbe`，只对 `d[B2_M_R]` 加一个精确修正项），前缀保住了。
但 v2 问的是"**软化/移除抑制能不能让 bit2 恢复认证**"——而在冻结工作点 n=6 上 bit2 **本来就认证**，
于是"能恢复"恒真。实测：基线在 n=6 已经计数，所以 `rdf_collapse_is_load_bearing` 是平凡真，
`check_rdf_collapse.py` 现在把该字段写成 `null` 并打印 `vacuity_text()`，不再输出"SUPPORTED"。

**结论**：把"崩塌 → 恢复"当作问法，在已经工作的点上必然空洞。提问方向必须反过来。

## 4. 正确的提问方向

> 从**能计数**的冻结工作点出发，**强行把 bit2 的 RDF 池往下压**，测：
> (a) 计数在什么池水平失效；(b) 失效点是否只由池水平决定，还是也由抑制曲线的形状决定。

这样得到的是**边界与余量**，而不是一句恒真的"能恢复"。

## 5. 实现要求（硬性）

1. **只动 bit2**。RDF 转录源只进入 `d[M_R]`，所以修正必须是**加性**的、
   形如 `d[B2_M_R] += (src_new - src_old) * scale`，其中
   `src = ZENG['alpha_rdf'] * S2 * rep(T2, K_rep, n_rep)`、
   `scale = base.lm * base.lu / (e.translation_h * base.kmat)`（v2 已用此式，可复用）。
2. **不改任何冻结文件**，不 patch 全局 `ZENG`。所有旋钮走子类参数。
3. **`n_A1_gate` 必须显式传入**（H1）：该子类直接构造 `ThreeBit51Model`，
   不继承 `build_threebit` 的安全默认；不传会静默回落到 4.0 —— v1 正是这么坏的。
4. **前缀结构对照（H5）**：每个旋钮在 factor=1 时，状态 0..33 的 RHS 必须**恰为 0**，
   轨迹必须**逐位相同**（`max|Δ| == 0.0`）。任何非零即说明修正漏到了别处。
5. **"动了哪些导数项"审计**：沿用 `audit_n_A1_gate.py` 的方法，
   对每个旋钮报出 `max|Δrhs|` 命中的索引集合，证明只有预期的 bit2 项在动。
6. 输出必须带工作点（`working_point.working_point_block`）与三档切尾的配对泄漏（H4）。

## 6. 四个旋钮 + 对照逻辑

| 旋钮 | 改什么 | 类别 |
|---|---|---|
| **K1** `K_rep` / `n_rep`（bit2-only） | 抑制曲线的位置/陡度 → 移动崩塌点 | **非线性**探针 |
| **K2** `alpha_rdf`（bit2-only） | RDF 源强度 → 纯剂量，不改曲线形状 | 对照 |
| **K3** `gamma_rdf`（bit2-only） | RDF 降解 → 反方向纯剂量 | 对照 |
| **K4** `alpha_rep`（bit2-only） | 抑制物驱动 → 沿同一 Hill 移动工作点 | 半对照（**需要第二处修正**：见下） |

K4 不同于 K1–K3：`alpha_rep` 进入的是 `d[b2_T]`（抑制物生成）而不是 `d[B2_M_R]`，
所以要**第二处**加性修正，并且同样必须通过 §5.4/§5.5 两项审计。这一点必须写进实现，不能想当然。

**对照逻辑（预登记）**：

- 若 K1 在"池还有相当水平"时就打掉计数，而 K2/K3 只有在池被压得低得多时才打掉
  → **结局 A（承重）**。
- 若四个旋钮的失效点都对应**同一个达到的池水平**
  → **结局 B（只是剂量）**。
- 若在网格可达的范围内（含 K2 把源压到接近 0）计数**始终成立**
  → **结局 C（不承重）**。

判据量：**认证 + `crossings == gates == 14`**（600 h，限定读窗判据全部沿用现有验证器），
并同时报出达到的 `min(b2_R)/b2_R_frozen` 比值，避免只看一个数就下结论。

## 7. 网格与成本

每个旋钮 6 档：factor ∈ {0.1, 0.3, 0.5, 0.8, 1.0, 2.0}；
4 个旋钮 × 6 = **24 点 × 600 h**（每点约 250 CPU-s）≈ **100 CPU-min**，分片 8 路约 15 分钟。
其中 factor=1.0 的四行必须**彼此逐位相同**（与 `preaudit_stochasticity.h2check` 同一逻辑），
用作 H2 自检。

## 8. 反证条件（什么会推翻结论）

- 出现任一旋钮在 factor=1 时前缀轨迹**不逐位相同** → 整个探针作废，先修实现。
- 失效点**不在**网格可达范围内（K2 把源压到 0.1 倍仍计数） → 只能写结局 C，
  且必须声明"池水平低到该程度时存储态仍成立"，不能反过来说"崩塌被证实"。
- 若某个旋钮改变的不是 bit2（§5.5 审计命中意外索引） → 该旋钮的结果不计入三个结局的判定。
