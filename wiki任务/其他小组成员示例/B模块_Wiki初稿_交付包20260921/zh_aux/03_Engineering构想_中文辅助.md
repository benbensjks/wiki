## 1. 工程问题与叙事主线

单比特模块要回答的工程问题：

> 怎样把一个连续振荡的上游信号，变成一个**每拍只走一步**的可靠数字存储元件？
> 为此需要在生物学上选择哪些元件、把它们的表达和清除调到什么范围、
> 并把这个范围变成实验组可以操作的指标？

叙事采用全项目统一的 **Question → Model → Result → Design decision** 与
**Design → Build → Test → Learn → Redesign** 双循环结构。

## 2. 工程循环（三轮 + 一次跨模块迭代）

### Round 1 — 从原文 TetR 到 BM3R1，并暴露输入接口问题

| 环节 | 内容 |
|---|---|
| **Design** | 把 Zhao 2019 单输入计数模块的 TetR 延迟电路换成与振荡器正交的 **BM3R1**；保留 ϕC31 Int/RDF 重组核心不变 |
| **Build** | 38 维 ODE：原文 35 条重组反应方程 + BM3R1 延迟电路 3 条；A 模块 v36 波形（周期 6.77 h、基线 0.28 µM）作为 Int 源 |
| **Test** | 移植验证（复现原文 LR 0.31/0.88 交替）、默认参数失效诊断、多维扫描（输入基线 / 延迟强度 / 标签 / K·n） |
| **Learn** | 1) 默认参数在新输入下失效；2) 失效机制是"基线泄漏自发翻转 + 延迟不足同脉冲回翻"；3) **唯一硬性接口要求是 int0 启动子泄漏 ≤1.5%**；4) 单靠计数器侧调参在旧波形下无解 |
| **Decision** | 向 A / 实验组提出 PLtetO1 泄漏收紧需求；给出 BM3R1 表达强度初版区间（$k_{BM3,tsl}$ 15–30 h⁻¹） |

**本轮 takeaway**：模型没有证明"可以工作"，而是**定义了接口边界**——
把"计数器为什么失败"变成 A 模块可以修改的具体指标。

> 本轮之后 B 报告做过一次 v3 修订（2026-08-01，依组内《核查报告》修正表述与补充二轮扫描重建），
> 属于"结果接受同行核查 → 修订交付"的工程记录，可在 Wiki 的 Engineering 页一笔带过。

### 跨模块迭代 — A↔B 接口的反馈与返工（Round 1 → Round 2 之间）

这是本项目最完整的一次 **设计反馈闭环**：模型之间的接口不是一次定义好的，
而是由两边的失效诊断共同修正的。两边的证据都写在各自 Week 4 报告里：

```text
B（Week 3）：真实波形下计数器失效
    ↓ 反馈：泄漏 / 基线 / 脉宽 是接口要求
A（Week 4）：显式 mRNA 模型 + 通量接口 v31(t)=ρ(t)β31m31(t)
    ↓ A 侧自查：旧波形配新周期仍可翻转，新波形配旧周期失败
    ↓ 定位：接口问题主要来自通量峰 / 剂量 / 脉宽组合，不是时钟周期
B（Week 4）：以 A 冻结输入重跑（返工）
    ↓ 交叉验证：与 A 的 v53g/v53h（RBS0.45 / tag8）独立结果一致（80/80）
B 补充结论：tag=12 窗口更宽、krdf,tsl 100 可用（tag12）、K 12–50 nM 全过
```

| 侧 | 动作 | 关键量化结果 | 出处 |
|---|---|---|---|
| B（Week 3） | 用 A 的 v36 波形驱动计数器，发现无解 | 唯一硬性要求：int0 泄漏 ≤1.5%；基线 ≤48 copies 才能计数 | B Week 3 §7.2–7.4 |
| A（Week 4） | 接口改为产生通量；自查新旧波形组合 | 通量脉宽 2.91 h → 3.45–3.62 h；"旧波形+新周期可翻转，新波形+旧周期失败" | A Week 4 §6.1 |
| A（Week 4） | 独立扫描 B 侧 RBS×tag 并做 A/B 自洽负载验证 | RBS 0.45 在 tag 4–20 h⁻¹ 可稳定翻转；RBS 0.45/tag 8 在 4 档负载 × 双初态 80/80 通过 | A Week 4 §7.1–7.2 |
| B（Week 4） | 返工：以 A 冻结输入重跑全部结论 | 旧工作点失效 → 新工作点；K 敏感带消失（12–50 nM 全过） | B Week 4 §5、§9.1 |
| B（9/19） | 启动子审查再次推翻工作点 | 非零泄漏 0.8% 下 Week 4 点失效 → 新方案（β_B=2、β_R=8、scale=0.30） | B 9/19 交付包 |

**写法建议（Engineering 页）**：把这一段写成"接口是被设计出来的，而不是被假设的"——
两个模块的模型在接口处对齐后，才允许做各自的参数扫描；
每次返工都由一个**可复现的失效**触发，并给出新的设计约束。
不要写成"沟通后修好了 bug"式的 routine troubleshooting（评审明确反对，见 §6）。

### Round 2 — A 定稿波形下的重验证与 Int 降解标签设计

| 环节 | 内容 |
|---|---|
| **Design** | 接受 A 的 Week 4 定稿输入（产生通量接口、周期 10.59 h、泄漏实测 0.5%）；把"Int 降解标签"作为正式设计变量 |
| **Build** | 接口改为 $J_I(t)=s_I\cdot v_A(t)$（µM/h），Int 的结合 / 稀释 / 标签清除由 B 侧处理；标签作用于所有含 Int 物种 |
| **Test** | 工作点重扫（表达 × 输入 × 标签）、RBS×tag 联合工作区、K/n 鲁棒性、异质性蒙特卡洛（30 实例/档） |
| **Learn** | 1) 新输入下工作点成立（双初态 score 0.995–0.998）；2) **K 敏感带消失**（12–50 nM 全过）——周期拉长后 RDF 恢复窗口充裕；3) 标签**必须有**（tag=0 必败），且窗口两端都有边界；4) 上界不是"峰被削平"的单调过程，而是 LR→PB 回翻失败的碎裂带；5) 随机全稳窗口（6–18 h⁻¹）比确定性窗口（3–24 h⁻¹）窄 |
| **Decision** | 给出实验组两件事：**RBS 0.45 / 表达配比 / 标签梯度标尺（原生 ssrA / LAA+4 / SsrA2X / LAA-LAA）**；并把"标签速率必须同条件实测"写成实验前提 |

**本轮 takeaway**：**标签不是可选优化，而是功能必需件**；
并且它的速率要与输入强度配对，不能只看标签序列本身。

### Round 3 — 启动子审查与非零泄漏下的方案重构

| 环节 | 内容 |
|---|---|
| **Design** | 审查实验组即将合成的 RDF 启动子；把"显式非零泄漏"纳入模型（Cello B1 门 $y_{min}/y_{max}=0.8\%$） |
| **Build** | 在 RDF mRNA 方程中加入不可被无限阻遏压低的泄漏底限 $\ell_R$；引入 Int 清除时 RDF 返回比例 $\eta$ |
| **Test** | 表达 × 输入 × 清除联合搜索；双初态长程 430 h；可行域网格（$\beta_B\times\beta_R$、$\ell_R\times\beta_R$）；启动相位与参数扰动；36 bp 序列来源核验 |
| **Learn** | 1) **Week 4 原工作点在 0.8% 泄漏下失效**；2) 重新匹配后存在方案：$\beta_B=2$、$\beta_R=8$、scale=0.30、$k_I=12$；3) 可行域是**宽平台**（$\beta_R$ 4–8 × $\beta_B$ 0.75–6）；4) **泄漏容差约 1%**，且泄漏底限随最大强度成比例放大——"越强的 RDF 启动子可能越不利"；5) 实验组提供的 36 bp 为 AI 生成且缺碱基，不建议原样合成 |
| **Decision** | 1) 启动子改为推荐已表征的 **Cello pBM3R1 66 bp**；2) 给出表达配比目标（BM3R1:RDF ≈ 1:4 最大产能）；3) 把"低谷启动"写进实验条件；4) 把 η 判别列为下一步关键实验 |

**本轮 takeaway**：**启动子"强度"不是越大越好，泄漏与强度成比例**；
设计目标从"选强启动子"改为"把表达配比与泄漏一起标定"。

## 4. Learn 清单：模型改变了哪些设计直觉

1. **"阻遏蛋白越强、延迟越足"是错的。** BM3R1 太强 → RDF 解锁过迟 → 回翻失败；
   太弱 → 同脉冲双翻。延迟必须落在"盖过脉宽、但不越过驻留期"的窗口内。
2. **"标签越快、清除越干净"是错的。** 标签上界存在碎裂退化带
   （LR→PB 回翻失败、周期卡滞），且上界随 RBS 上移。
3. **"RDF 越强越好"是错的。** 非零泄漏下，RDF 最大强度与泄漏底限成比例放大，
   过强的 RDF 启动子会破坏可行域（高泄漏必须配低 $\beta_R$）。
4. **工作点不是常数。** 输入波形改变（周期 6.77 → 10.59 h）会整体移动工作带
   （K 敏感带消失、tag 窗口变宽）；启动子泄漏改变（0 → 0.8%）会推翻整个工作点。
   设计交付必须是"窗口 + 条件"，不能是"一组数"。
5. **初始化是设计条件。** "任意相位接入"未通过（37/40）；
   低谷启动 + 已知初态是当前方案的一部分，应在实验方案里显式安排。
6. **接口语义决定结论。** A→B 必须传产生通量（µM/h）而不是浓度，
   否则标签/稀释会被重复积分；这类接口错误不会在单模块调试中暴露。
7. **返工是设计流程的一部分，不是失败。** 三次工作点更替（v36 → Week 4 → 非零泄漏）
   每次都来自一个新的、可复现的失效，并产出更明确的设计约束。

## 5. 与实验的接口（下一轮 Redesign 的输入）

按优先级：

1. **表达标定**：测当前构件的 BM3R1 / RDF 稳态表达与泄漏，
   换算成 µM / 拷贝数，与第 3 节目标对照后调 RBS（或启动子档位）；
2. **Int 清除速率**：测 Int–标签融合蛋白的去诱导降解曲线，
   按配对规则选择输入 scale；若实测 $k<3\ \mathrm{h^{-1}}$ 考虑 ClpX 共表达；
3. **η 判别**：以同条件 RDF 稳定性 / 含量变化判断 Int 清除是否额外消耗 RDF；
   若显著存在，切换到 $\eta=0$ 备选参数组并重扫；
4. **pBAD-INT 分步表征**：先用可控输入（方波对照：峰 2 µM/h、宽 2–3 h 通过）
   表征开关，再接入 A 振荡器并检查初始化。

## 6. 评审口径对照（2026 Judge Handbook / Best Model）

### 6.1 Best Model 的四个评分维度（handbook 原文口径）

1. How impressive is the modeling?（跨度 / 集成 / 工程用途）
2. Did the model help the team understand a part, device, or system?
3. Did the team use measurements of a part, device, or system to develop the model?
4. Does the modeling approach provide a good example for others?

**B 模块的对应素材**：单比特属于"device level"（开关机制 + 翻转窗口）；
"用测量发展模型"目前主要是文献测量（Zhao/Pokhilko 参数、Cello 门表征），
队伍自身测量尚缺——正文必须如实标注，不虚构验证闭环。
"可复用"素材：窗口扫描脚本、判据脚本与参数表可直接被其他队伍替换使用。

### 6.2 iGEM 工程方法学清单（handbook "On Engineering"）

- 明确问题并展示理解 → 收集数据（引用来源）并识别未知与约束 →
  选择指导原理 → **列出假设、近似与简化** → **建立可量化的成功判据** →
  展示问题如何被解决 → 验证结果 → 沟通方案。

**B 模块逐项对照**：假设与证据标签已显式（§3、wiki 初稿 §12）；
成功判据为端点 $Q$ + 中点穿越 + 计数奇偶性（公开定义）；
"验证"为双初态长程 + 扰动 + 异质性 MC（均为模型内验证）。

### 6.3 两条来自 handbook 的警示（写作时必须避免）

1. **不要把工程写成"日常排错"**：handbook 收录的评审反馈原文指出
   "much of your work under the engineering criterion reads more like routine
   troubleshooting than actual design-driven engineering"。
   → 我们的每次返工都要写成"设计问题 → 模型判据 → 设计决策"，
   而不是"发现报错 → 修好"。
2. **"失败是工程的一部分"**：handbook 引用 "Failure is central to engineering"，
   并明确成功与失败同样有价值。
   → 三级级联失败、标签上界碎裂带、非零泄漏推翻工作点都应保留在 Wiki 中，
   说明它们如何改变设计。

## 7. 外部对标：Engineering 与 Wiki 写法（批判学习）

> 以下为 2026-09-21 实际访问的公开 Wiki 观察（访问日期同）。引用仅用于写作方法对标。
> **方法提醒**：部分 iGEM Wiki 的正文是浏览器端渲染的，直接 HTTP 抓取会看到空页；
> 以下页面均经浏览器渲染（headless Chrome）核对后再分析。

### 7.1 IZJU-China 2025（Engineering 页）

**形式**：整页按 DBTL1 → DBTL2 → DBTL3 → DBTL4… 组织，
每个 DBTL 内部固定 **Design / Build / Test / Learn** 四段；
长流程再拆子编号（如 DBTL3.1–3.4），每段配图与图注、数据表、文末参考文献。

**值得学**：

1. **一个 DBTL = 一个设计决策**（选靶点、选切割方案、选递送、选破膜），
   标题本身就是决策名，读者一眼看到"每一轮改了什么"；
2. **失败与放弃写得很实**：如 Cas9-FITC 标记回收率低 → 放弃 → 改用 sgRNA-FITC；
   电泳判读被 marker 干扰 → 放弃 → 改用 UV-Vis。每一步都给了"为什么放弃"和"下一步"；
3. **数字密度高**：AUC、回收率、标记效率、显著性检验全部落表；
4. **图注承担论证**：图注不是"图示"，而是写清条件、对照、结论。

**要批判/不能照搬**：

- 极重湿实验（凝胶、AFM、UV-Vis），**干实验项目没有这种素材密度**，
  硬学会造成"为了显得工程而堆实验"；
- 部分 Learn 只是复述结果（"信号随激酶增加"），没有提炼成可迁移的设计规则；
- 页面很长，靠子编号和锚点管理，若没有同等导航设计会劝退读者。

### 7.2 Heidelberg 2025（Engineering 页）

**形式**：Engineering 页先给 Wet Lab / Dry Lab / HP 三块总览卡，
主体按 "Processing → Responding → …" 的工程阶段组织，
每阶段内是 Iteration 1…n，每个 iteration 又是 **DESIGN / BUILD / TEST / LEARN**；
图表密集、统计检验（ANOVA 等）直接标在图上。

**值得学**：

1. **迭代编号 + 一行结论**：读者按编号就能看出"第几轮、解决了什么"；
2. **对照与反证意识强**（催化失活突变体、无卷曲螺旋版本），
   把"功能确实来自设计机制"证到；
3. **图注含方法细节**（转染量、时间、归一化方式），可复现性好。

**要批判/不能照搬**：

- 同样是湿实验主导；其"Learn"有时只写"下一步要做什么"，
  对"这一轮如何改变整体设计"着墨较少——这正是我们（建模主导项目）可以做得更好的地方。

### 7.3 USTC 2025（我校前一届）

**形式**：Engineering 页按 **Iteration 1–4** 组织，每个 Iteration 内含若干 cycle，
每个 cycle 固定 **Design / Build / Test / Learn**（约 3.5 万字符）；
Model 页给出五个模型，每个含 Objective / Challenges / Equations / Parameters / Results /
**Guidance to Wet Lab** / Discussion / References，并自带一个交互平台
（静态 HTML，托管在队伍自己的网页目录内）。

**值得学**：

1. **Iteration + cycle 编号配一行标题**（如 "Iteration 3: Optimize the strain ratio (Model)"），
   读者能逐轮追踪设计动作；
2. **失败与转向写得很实**：二维高斯拟合模型因实验数据不足无法验证 → 转向机理模型优先；
   "自更新"算法误差大被放弃 → 催生新的 "flux" 算法——失败与转向都有记录；
3. **每个模型以 "Guidance to Wet Lab" 收尾**——正是评审要看的"模型 → 设计决策"接口，
   我们第 3 章应照此补一个明确的收尾块；
4. **交互内容自托管**在队伍网页目录内，符合"Wiki 不能外链"的组内要求。

**对我们的启示**：Iteration 编号、如实记录失败与转向、"Guidance to Wet Lab" 收尾块都可直接借鉴；
把模型驱动的 D/B/T/L 保留在同一页并用链接显式连接。

## 8. 边界与写法约定

- **不写"已验证"**：全部结论为模型预测；实验标定完成前使用"候选工作点""模型目标"表述；
- **不混用参数组**：Week 4（零泄漏假设）与非零泄漏方案是两套模型条件，
  参数与结论不得交叉引用；
- **不把工程判据写成实验标准**：$Q$、中点穿越、计数奇偶性均为工程验收判据，
  正文须同时给出定义与原始轨迹；
- **不把返工写成排错**：每次返工对应"新失效 → 新约束 → 新工作点"；
- **不宣称完整自杀 / 清除系统**：本章只覆盖单比特计数与输出时长接口，
  效应器与细胞清除不在范围内。
