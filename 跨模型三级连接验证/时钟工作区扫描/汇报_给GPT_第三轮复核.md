## 2. 对 round 5 / 5b 的逐项复核

### 2.1 Part C：同刻通量统计（`round5_20261001_173156/partC_flux.*`）

对象：27 条轨迹（14 通过 / 13 失败），逐条算三种标量，看哪种能把通过组与失败组分开。

| 标量 | 通过组区间 | 失败组区间 | 是否判别 | 我的判读 |
|---|---|---|---|---|
| `max_same_time_IR_over_threshold` | [2.1750, 16.2164] | [0.1019, 4.4402] | **否** | 重叠区 [2.1750, 4.4402] |
| `v_rev_over_v_fwd_at_max` | [0.9824, 1.3481] | [0.0686, 1.4996] | **否** | 通过区间**整个含于**失败区间内，最坏情形 |
| `int_ratio`（时间积分） | [0.7617, 0.8063] | [0.0639, 0.6338] | **是** | 间隔 (0.6338, 0.7617)，宽 0.1279 |

三点补充（都是我独立重算得到的）：

1. **`max_same_time_IR_over_threshold` 只是一个常数缩放**，不是「越阈」：源码 `diagnose_round5.py:111` 是 `float(ir[j] / KD_COMP)`，`KD_COMP = 0.8`。逐行核对：`max_same_time_IR / over_threshold` 恒等于 0.8。因此该列与 `max_same_time_IR` 携带的信息完全相同，不宜作为独立指标列在表里。
2. **`int_ratio` 的判别性是真的，但它是「结果的复述」，不是机制判据**：`∫v_rev/∫v_fwd` 由 `pb2` 的占空比主导，而 `pb2` 就是**被计数的那个位**。位在翻转 → 比值落在 0.76–0.81 的窄带；位卡死 → 两条通量之一被系统性掐掉 → 比值跑偏到 0.06–0.63。它区分的是「位有没有翻」（=结果），不是「门为什么开不了」（=原因）。**对方的 `make_figures3.py:104,109-110` 与图内文字已经自行写明这一点**（"only the integrated ratio separates - and it restates the outcome"、"must not be sold as an independent mechanism criterion"）。我独立得出同一结论，**这条不算缺陷，算双方独立收敛**。
3. **旧的 peak×peak 指标错得最厉害的地方，恰恰是「能工作」的那一档**：
   - 全表最大夸大 **6.5466×** = 11.391107437637922 / 1.7400241411266346，出现在 `round4b / traj_bypass_K0.40_on.npz`，这是一条**通过**的轨迹；
   - 13 条失败轨迹里最大夸大只有 **2.1114×**（`round2 / traj_K0.30_on.npz`），其余 12 条 ≤ 1.0864×，最小 1.0006×。
   - 含义：如果只看失败组去检验这个指标，会得到「peak×peak 和同刻值差不多」的错误安心感；真正的荒谬只在工作/临界档暴露。这与 `fig3_mechanism` 的撤回理由一致，且给出了「为什么当初没被发现」。

**结论：Part C 的结论成立**，`fig3_mechanism_v2` 的标题「本族中没有任何同刻标量能判别通过/失败」准确。

### 2.5 本轮新发现的缺陷

#### 缺陷 A（中）：`check_errata.py` 把「自馈开关」当成「计数判读」

```
106:  cases = [
107:      ('base fail  K=0.40 off  (no bypass)', ..., False, 0.40),
...
111:      ('bypass   K=0.40 off',             r4b/'traj_bypass_K0.40_off.npz', False, 0.40),
```
元组第 3 位在 `cases` 里是 **autoregulation（自馈）开关**，用于 `D.HZZModel(prefix, ok)`（第 127 行）。但同一位随后被当成判读结果使用：

```
138:  print(... 'pass' if ok else 'fail' ...)      # ← 把臂标成了结论
139:  table.append(dict(case=name, counting=ok, ...))  # ← 字段名叫 counting，装的是开关
```

后果（可对照同目录 `partC_flux.json` 直接验伪）：

| 用例 | `errata_check.json` 的 `counting` | 同批轨迹在 `partC_flux.json` 的 `counting`/`events` | 一致？ |
|---|---|---|---|
| base fail K=0.40 off | false | false / false | ✓（碰巧对，因为 off=失败） |
| base fail K=0.25 off | false | false / false | ✓（碰巧对） |
| clk020 pass K=0.20 **off** | **false** | **true / true** | ✗ 矛盾 |
| bypass K=0.40 **off** | **false** | **true / true** | ✗ 矛盾 |
| bypass K=0.40 on | true | true / true | ✓（碰巧对，因为 on=通过） |

即：**5 行里 2 行错，且错法系统性**——凡「自馈关但计数通过」的组合都会被写成 `counting:false`，stdout 也会把它打印成 `fail`。`off` 恰好同时是「源文件真实行为」和「失败臂」的默认假设，所以这个 bug 在只有 off 臂的早期轮次里不会暴露。

**严重程度：中。** 它不是头条结论，但它是**专门用来确认纠正是否到位的文件**；同一结果目录里两个文件用了同名不同义的 `counting` 字段，是会被下游无声继承的那类错误。

**建议**：把第 3 位重命名为 `autoregulation`，`counting`/`events` 改由 `evaluate()` 现算（与 `partC_flux.json` 同源），`print` 里的 `pass/fail` 删掉或改为 `arm=on/off`。

#### 缺陷 B（低）：被跳过的用例不留痕

```
122:  if not path.exists():
123:      print(f'  (missing {path.name})')
124:      continue
```
`cases` 列了 6 个用例，实际只有 5 个进了 JSON——因为 `round2_20261001_133639/traj_K0.20_on.npz` 不存在（该目录只有 `K0.25_on / K0.30_on / K0.35_on`）。缺失只在 stdout 出现，JSON 里既无该行也无 `skipped` 标记。**读者会把 5 行当成全部。**

## 3. round 4 Part A「相位依赖」的处置建议

**问题**：round 4 Part A 记录 `phase 7` 的 `event_causality_passed = False`，据此写下「计数依赖相位」。要不要把它标成「构造已作废、结论不保留」，还是靠延长 burn-in 救？

**我的建议：标注为「已被取代（superseded）」，并把「计数依赖相位」这个结论作废、不保留；不要用延长 burn-in 去救。** 五条理由，全部可在盘上验证：

**（R1）构造名不副实：那八个「相位」都在同一个时钟周期内，且数字值全是同一个。**
`diagnose_round4.py:124` 用 `targets = (pt[-2]-period) + i*period/8`，即**以「一个时钟周期」为间隔单位**取 8 个点，跨度 `period*7/8 = 9.202 h < 10.517 h`。而异构计数器**每个时钟周期只加 1**，所以这 8 个采样点全部落在**同一次计数**之内：`errata_check.json: problem1` 实测 `distinct_values=[2]`、`undecided=1`。它们不是计数的 8 个相位，而是**单个计数内部的 8 个子相位采样**。要覆盖 0–7 必须跨 `8*period = 84.13 h`。

**（R2）构造本身把上游时间重置为 0，快照因此不在受驱极限环上。**
`diagnose_round3.integrate_from` 调 `solve_ivp(model.rhs, (0, HOURS), y_snapshot)`。23 态模型**不携带上游振荡器状态**（`HZZModel.rhs → prefix.bit0_rhs(t, y[:11]) → han.interp(60*t, h31)`），所以上游相位从 t=0 重启。快照是「在原上游时间下长出来的状态」，却被「重置后的上游」驱动 = **离吸引子的初值**。

**（R3）失败发生在 bit0→bit1 这一级——而这一级根本收不到末级的任何影响，所以它和时钟门、和 ZMH 末级都无关。**
`phase_unmatched_both_stages_round4_*.json` 显示 phase 7：`stage0` 19 反向 / 18 门 / 18 翻转，`passed=false`，`one_to_one/order/alt` 全 false；而 `stage1`（bit1→bit2，ZMH 末级）9/8/8 **passed=true**。方向搞反了：坏掉的是**已经被认证的 HBY 老那一级**，没坏的是新末级。前缀对末级状态免疫是**已证**的（`structural_checks` 把末级状态放大 100 倍后 `prefix_rhs_gap` 仍**恰为 0**；我本轮 preflight 复现亦为 0.0）。所以 phase 7 的异常**只可能来自被重置的上游 + 离吸引子的初值**，与「相位」无关。

**（R4）延长 burn-in 修不了，而且会掩盖真问题。**
phase 7 stage0 的那个不配对事件是 `reverse_id=2, reverse_peak_h=43.7`，其 `in_dropped_burnin` 字段为 **false**——它已经在现有 `DROP=2` 的剔除区之外（真正落在剔除区里的是 `reverse_id=1 @24.37 h`）。所以把 burn-in 拉长，只是在 43.7 h 之前多剔几个事件：**问题不在视界里，在构造里**。若要靠「多剔几个」让它消失，等于把一个离吸引子瞬变从记录里删掉，而不是回答「计数是否依赖相位」。这与本项目已确立的纪律（`fig4_eight_phases` 是**撤回**而不是**加 burn-in**）一致。

**（R5）正确的实验已经做过，而且答案是否定的。**
round 5 Part D 与 round 5b 用 `TimeShifted`（`dy/dt = f(t + t_start, y)`）保留了上游时间，八个初态取在**读窗谷底**、跨度 `74.12 h = 完整一个 mod-8 周期`、覆盖数字 1–7 与 0 → **8/8 全通过**。这正是 Part A 想问的问题的正确版本。因此 Part A 的状态是「**已被取代**」而非「结果不保留」：它的构造被替换了，它的问题被更好地回答了。

**措辞建议**（可直接抄进文档）：

> round 3/4 的「八相位」构造**已被取代**：它以「一个时钟周期」为间隔取样，8 个点跨 9.20 h、全部落在同一个数字值（2），且续算把上游时间重置为 0。其所报告的 `phase 7 event_causality_passed=False` 发生在 bit0→bit1 一级（该级对末级状态免疫，前缀 RHS gap 恰为 0），因此不能支持「计数依赖相位」。该结论**作废、不保留**。正确版本见 round 5b Part D：保留上游时间、八初态跨一个完整 mod-8 周期 → 8/8 通过。

**同时必须保留的一条边界（不要说成「相位已证明无关」）**：

> 上述全部证据都在 **`clock_K = 0.10`（已认证工作点）** 上取得。**接近计数边界（临界 `clock_K`）时，初值/相位的敏感性仍未测**。round 5b 的 8 个初态都是**同一条收敛轨道上的读窗谷底**，因此 8/8 的含义是「从哪个数字起步都一样」，**不是**「任意受扰状态都能恢复」。若要关闭这条边界，最小实验是：取 8 个初态 × 2–3 个跨在失败边界两侧的 `clock_K`，用 `TimeShifted` 同法续算。

## 4. 我新建的脚本与设计理由

目录：`跨模型三级连接验证/时钟工作区扫描/`

**为什么两套模型可以并列扫描（一个能省掉一半工作的结构事实）**

- HZH 34 态 = **17 态公共前缀** + HBY 的 A1/F1 6 态 + HBY bit2 11 态
- HZZ 23 态 = **同一个 17 态前缀** + ZMH 6 态末级
- 前缀对末级**无反馈**（结构护栏实测 `prefix_rhs_gap == 0`，把末级状态乘 100 仍为 0）
- ⇒ **两套末级收到的 `Int0(t)` 是逐点相同的同一个信号**（HZH 取 `y[2]`，HZZ 也取 `y[2]`）

## 5. 附加核查：`receiver_uM_per_au` 是不是活参数（决定 group 2 该不该跑）

**动机**：本来计划第二组扫 `uM × clock_K`。但 `hybrid_model.py:160` 的注释说这个字段
"metadata only"。如果注释是对的，那么扫 uM 就是**扫空气**（同目录 `fig5_bypass` 的教训：
不同 `clock_K` 结果完全相同，只因该参数已不进入动力学）。所以在花 40 min 之前先量一次。

**实测一：它进动力学（`check_uM_is_dynamical.py`，60 h，同一条 Han 上游）**

| 模型 | uM | ×f | `max\|Δy\|` | `Int0` 峰值 | 峰值比 | `copies_per_au` |
|---|---|---|---|---|---|---|
| HZH / HZZ | 2.875 | 0.50 | **3.771e+01** | 1.09618 | 1.9986 | 1731.365 |
| HZH / HZZ | 4.600 | 0.80 | **1.491e+00** | 0.68553 | 1.2499 | 2770.185 |
| HZH / HZZ | 5.750 | 1.00 | 0 | 0.54848 | 1.0000 | 3462.731 |
| HZH / HZZ | 8.625 | 1.50 | **2.597e+01** | 0.36568 | 0.6667 | 5194.096 |

- `max|Δy|` 在 uM 改动下**远非常数 0** ⇒ 注释 "metadata only" **与行为相反**。
- `Int0` 峰值比与 `1/f` 相符到 **0.07%**（×0.8 → 1.2499 vs 1.25；×1.5 → 0.6667 vs 0.6667）
  ⇒ uM 的首要作用是**把上游信号整体缩放**，`copies_per_au = 602.214076·uM` 就是那个换算系数
  （`model_hzh.py:29,37,49,81`）。
- HZH 与 HZZ 两套数字**逐位相同**——因为二者共用 17 态前缀，而 uM 只作用在前缀上。

**实测二：它与 `clock_K` 是否近似简并（`check_uM_vs_clockK.py`，60 h，看判读真正看的量）**

理论预期：门只通过 `hill(clock_scale·Int0, clock_K, n)` 吃 `Int0`，而
`hill(s·x, K, n) ≡ hill(x, K/s, n)` 精确成立，所以"把 `Int0` 按 `1/f` 缩放"应当等价于"把
`clock_K` 乘 `f`"。实测**否**：

| f | `uM×f` vs 基线：dTail / dSwitch / dg1 / dPeak(h) | `clock_K×f` vs 基线 | **`uM×f` vs `clock_K×f`** |
|---|---|---|---|
| 0.50 | 7.46e+00 / 9.81e-01 / 3.88e-01 / 0.117 | 1.64e+00 / 1.47e-01 / 1.49e-01 / **0.000** | 7.43e+00 / **9.81e-01** / 5.36e-01 / **0.117** |
| 0.80 | 1.31e+00 / 3.69e-01 / 1.41e-01 / 0.017 | 6.54e-01 / 6.42e-02 / 5.96e-02 / **0.000** | 1.00e+00 / **3.18e-01** / 1.73e-01 / **0.017** |
| 1.50 | 7.37e+00 / 8.54e-01 / 3.78e-01 / 0.067 | 1.34e+00 / 1.67e-01 / 1.22e-01 / **0.000** | 7.42e+00 / **8.29e-01** / 2.56e-01 / **0.067** |

（HZH；`dSwitch = max|ΔS0,ΔS1,ΔS2|`，`dPeak` = `Int0` 峰时刻最大移动）

两条**相互独立**的理由说明它们不等价：

1. **uM 会动读窗时刻，`clock_K` 不会。** `clock_K` 只出现在末级门里，前缀对它完全免疫，
   所以 `dPeak` **恰好为 0.000**；而 `uM×1.5` 把 `Int0` 峰时刻移动了 **0.067 h**，
   `uM×0.5` 移动了 **0.117 h**。读窗是按 `Int0` 峰/谷定义的，所以 uM 是**唯一**会同时
   改动"门强度"和"取样窗口"的轴——它动的是时序裕度，不只是门的开度。
2. **uM 把整个前缀搬到另一个工作点。** 开关态差 `9.81e-01 / 3.18e-01 / 8.29e-01`，
   与"uM 对基线"的差同量级，而 `clock_K` 对基线的差只有 `1.47e-01 / 6.42e-02 / 1.67e-01`。
   原因：`copies_per_au` 同时进了 `initial_state`（`model_hzh.py:81`），所以初值也被缩放。

**结论**：`uM` 是一条**真实的、独立的、且至今未标定**的轴，group 2（`uM × clock`）值得跑；
但报告里必须**分开写**它移动的是"读窗时刻 + 门强度"两件事，不能像 `clock_K` 那样只用
一个 `r = K/Int0_peak` 概括。同时建议修掉 `hybrid_model.py:160` 的注释——按现状，任何
"只碰 `HbyReceiver` 不碰 `HZHModel.copies_per_au`"的 harness 都会得出"uM 是空操作"的假结论。

轴向设计：

- `clock_K ∈ {0.075, 0.15, 0.20, 0.22, 0.24, 0.26, 0.28, 0.30, 0.40, 0.60}`
- 时钟 Hill 指数 `n ∈ {2, 3}`；HZH × 1 臂；HZZ × 2 臂（自馈关 = 源文件真实行为 / 自馈开）
- 合计 10 × 2 × 3 = **60 个点，300 h/点**（约 50 min）
- **`Int0_peak = 0.54848` ⇒ `r = K / 0.54848`**（两套模型收到的 `Int0(t)` 逐点相同，见 §4 的结构论证）

### 6.1 成功区（本轮最强的一条结论）

| 模型 | 臂 | n | 成功 K 区间 | 对应 r 区间 | 高 K 端失效方式 |
|---|---|---|---|---|---|
| **HZH** | base | 2 | **0.075 ~ 0.60（全通过）** | 0.137 ~ 1.094 | **未出现** |
| **HZH** | base | 3 | **0.075 ~ 0.60（全通过）** | 0.137 ~ 1.094 | **未出现** |
| HZZ | off | 2 | 0.075 ~ 0.22 | 0.137 ~ 0.401 | K=0.24 起失败 |
| HZZ | off | 3 | 0.075 ~ 0.22 | 0.137 ~ 0.401 | K=0.24 起失败 |
| HZZ | on | 2 | 0.075 ~ 0.26 | 0.137 ~ 0.474 | K=0.28 起失败 |
| HZZ | on | 3 | 0.075 ~ 0.26 | 0.137 ~ 0.474 | K=0.28 起失败 |

- **HZH 在 8 倍 `K` 范围内 20/20 全通过**，且逐点行为**完全一致**：19 个稳态窗、序列 `1234567012345670123`、最小时序裕度 `1.1785 h`、`S2` 承诺 `1.0`、边界裁剪 `0`、S2 翻转 7。
  即便 `K=0.60`（`r=1.094`，时钟门峰值开度只剩 `hill(0.548,0.6,2)≈0.455`、每周期门剂量掉到 `3.1e-4`）仍照常计数 ⇒ **已认证 HZH 的时钟门不是**本范围内的约束条件**，其上界在 `K>0.6` 之外。**
- **HZZ 的窗口窄得多：自馈关 `K≤0.22`、自馈开 `K≤0.26`。** 两者的下界都没出现（`K=0.075` 仍通过）。

### 6.2 边界由「阈值位置」决定，不由「门的陡度」决定

`n=2` 与 `n=3` 在**三个组上给出完全相同的边界**（`hzh` 0.60/0.60、`hzz|off` 0.22/0.22、`hzz|on` 0.26/0.26）。

⇒ 在这个模型族里，把时钟 Hill 指数从 2 提到 3 **不移动成功区**。`n` 影响的是门剂量的绝对大小（例如 `hzz|on|K=0.075` 从 `1.44e-3` 到 `1.46e-3`），不是"过不过"。
**这条直接回答了第 2 个问题：两套模型的差异不是陡度差异。**

### 6.3 差异来自末级自身，不是时钟门（跨模型对照）

在**同一个 `r`** 上逐点对照 HZH 与 HZZ(自馈开)：

| r (=K/0.54848) | K | HZH | HZZ(开) |
|---|---|---|---|
| 0.137 ~ 0.474 | 0.075 ~ 0.26 | PASS | **PASS** |
| **0.511** | 0.28 | **PASS** | **counting 失败**（事件链仍通过） |
| **0.547** | 0.30 | **PASS** | **两级都失败** |
| **0.729** | 0.40 | **PASS** | **两级都失败** ← 这正是已发布的 HZZ 失败点 |
| **1.094** | 0.60 | **PASS** | **两级都失败** |

**同一个 `Int0(t)`、同一个无量纲比值 `r`，HZH 通过而 HZZ 失败。** 因此 `clock_K=0.40` 的失效**不是时钟阈值现象**：若它是，那么具有同样 `r` 的 HZH 也应当失败。差异只能落在末级自身。

**而且它也不是"门的三因子乘积太弱"——这一条是本轮最反直觉的结果。** 同一点上逐点对比**每周期门剂量** `∫g1 dt`：

| K | r | HZH（判读） | HZZ 自馈开（判读） | HZZ 自馈关（判读） | 开/HZH |
|---|---|---|---|---|---|

**在 `K=0.28` 与 `K=0.60` 两点，HZZ（自馈开）与 HZH 的每周期门剂量相差不到 10%，判读却相反。**
⇒ 成功与失败的分界**不在门剂量上**，而在"同样的 `Int2` 生产速率能不能把 bit2 推过 0.3/0.7 带"这一步，也就是末级的**表达/翻转阈值**
（ZMH：`alpha_Int2=28`、`gamma_int2=2`、`K_D_int2=1`；HBY：`alpha_Int[1]`、`gamma_int[2]`、`K_D_int[2]`）。
这与早先记录的"源文件 `前馈三级级联.py:107` 常数不匹配（`int0` 平台 3.0 vs 实测峰值 0.548，5.47×，再被三次 Hill 放大）"**方向一致但落点不同**：不匹配的后果不是"门开不了"，而是"门开了也不够"。

### 6.4 失效的**顺序**：先丢承诺，再断事件链

刚过边界时的失效方式并不都是"两级同时崩"：

| 点 | 判读 | 序列片段 |
|---|---|---|
| `hzz\|off, n=3, K=0.24` | **counting 失败、事件链仍通过** | `xxx456701234567xxxx` |
| `hzz\|on, n=2 / n=3, K=0.28` | **counting 失败、事件链仍通过** | `xxx4567012345670123` |
| `hzz\|off, K=0.26` | 两级都失败 | `567456745674567xxxx` |
| `hzz\|off, K=0.40（n=3）` | 两级都失败 | `xxx4567456745674567` |
| `hzz\|off, K=0.60（n=3）` | 两级都失败，S2 **0 次翻转** | `1230123012301230123` |

⇒ 门先关到"位还能走、但读窗里有窗口落不进 0.3/0.7 带"（`minimum_commitment` 掉到 `0.0`、`S2` 带裕度转负），**再**关到"反向事件根本不起"。
这也解释了为什么单看 `counting` 或单看 `events` 会给出不一致的边界印象——**边界上先丢的是承诺**。

### 6.5 「自馈开」值多少

- 边界：`K ≤ 0.22`（关）→ `K ≤ 0.26`（开），即成功区上界从 **r = 0.401 → 0.474**，**+18%**（ΔK = 0.04）。
- 机制：负自馈把**每周期门剂量放大 6.0 倍**（`K=0.075`：`2.4e-4 → 1.44e-3`；`K=0.22`：`1.4e-4 → 0.82e-3`），
  即把 ZMH 末级的门剂量从"HBY 的 1/6.5"提到"与 HBY 相差 10% 以内"——而这只换来 **+18%** 的窗口。
- 在 20 组同 (`K`,`n`) 对照里，**16 组判读相同、4 组不同**，且不同**全部**是"开关通过、关失败"（`K=0.24`、`0.26` × `n=2,3`）——**没有一组是开比关差**。
- 意义：负自馈不是"开关式"的救命参数，而是**把门剂量提高 6 倍、把无量纲时钟裕度提高 18%**。这比"有/没有自馈"的定性说法准确得多，也正是把 ZMH 源文件真实行为（自馈关）与已认证行为（自馈开）对齐时需要补的量。

### 6.6 本轮没有回答的（边界声明）

1. **HZH 的上界仍未找到**（`K>0.6` 或 `r>1.09`）。若要说"HZH 的时钟门有上界"，需要补 `K ∈ {0.8, 1.0, 1.2, 1.6}`。
2. **`K=0.075` 处两者都通过**，所以**下界也没找到**。若要说"HZH 的时钟门在下侧会失效"，需要补更小的 `K`。
3. 边界的**位置精度只有网格步长**（`hzz|off` 落在 (0.22, 0.24]、`hzz|on` 落在 (0.26, 0.28]）。要报边界值本身，需要在各自区间内加密到 0.005。
4. 全部结果都在 `uM = 5.75`、`alpha_Int2` 取基线值。**uM 轴与 `alpha_Int2` 轴没跑**（见 §5：uM 不是空轴，值得单独跑）。
