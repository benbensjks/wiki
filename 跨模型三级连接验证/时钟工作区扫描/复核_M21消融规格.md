## 2. D1（高）：34 态 HZH 的判读器**不读**模型的 signals 字典

### 2.1 结构差异

| | HZZ（23 态） | HZH（34 态） |
|---|---|---|
| 判读入口 | `diagnose_round3.evaluate(t, sig, hours)` | `verify_hzh.analyse(t, y, zmh, receiver)` |
| `sig` 从哪来 | **调用方提供** ⇒ `mb.signals(y)` 的改写会一路传进去 | `analyse` 内部自己调 `verify_hzh.signals(y, zmh, receiver)` **重算** |
| 结果是 | round 4b 的旁路**能被判读看见** | 旁路**判读看不见** |

`verify_hzh.analyse:164` 是 `sig = signals(y, zmh, receiver)`；`verify_hzh.signals:60-75` 用 `y` 与 `receiver.c` / `receiver.p` **重新算** `g0, g1, clock, J_rev0/1/2, J_fwd2, S0, S1, S2`。它**从不调用** `HbyReceiver.signals`。

### 2.2 实测（`check_hzh_bypass_plumbing.py`，60 h）

只替换第三个因子（`clock ≡ 1`）的 `BypassTail(HbyReceiver)`：

```
max|y_bypass − y_normal| = 2.529302e+00        <- 动力学确实被旁路了
旁路轨迹上的 clock：min=0.00000  max=0.76972   <- 0.76972 而不是 1
analyse(旁路轨迹, 原始 receiver) == analyse(旁路轨迹, 旁路 receiver) ?  True   <- 判读完全看不见
门峰值处：判读器用的 g1 = 0.388675（act·repress·clock）
          旁路后的  g1 = 0.612762（act·repress）      比值 1.5765
整条轨迹：判读器 g1 峰值 0.388675 vs 旁路 g1 峰值 0.614499，最大差 2.288591e-01
```

**判读器把被删掉的 `clock` 因子又乘了回去**——它数的是"门还在"的那条脉冲链。这正是 round 4 那个 bug 的形状，但在 HZH 上**改字典键修不了**，因为判读器根本不看那个字典。

> 注：60 h 的两条轨迹 `counting` 都是 False，那是因为只有 5 个读窗（判据要 ≥24），不是动力学结论；这里只用它证明"判读看不见旁路"。

### 2.3 可行的正确路径（已验证）

```python
sig = common.sig_of(mb, yb, 'hzh')     # 对 hzh 也是调 verify_hzh.signals —— 仍会重算
sig['clock'] = np.ones_like(sig['clock'])   # 覆写必须在 sig_of 之后
sig['g1']    = g_bp                          # 旁路后的 act·repress
v = common.verdict(tb, sig)                  # 与 analyse 逐字段 parity 守卫过
```

这正好是 `时钟工作区扫描/common.py` 存在的理由：`verdict(t, sig)` **把 sig 交出来**，而 `parity_guard()` 断言它在未旁路时与 `verify_hzh.analyse` 逐字段一致——所以这里不是"第二套判读逻辑"，只是把签名换成可注入的形式。

**同时建议在 §4 的护栏里补上 `parity`**（现在的护栏只有前缀复现那一条）。前缀复现证明的是"没跑错模型"，parity 证明的才是"这张图的判据没被旁路悄悄改成另一套"。

## 3. D2（中）：`clock_K = 0.10` 不是 34 态 HZH 的认证工作点

`hby_zmh_hby` 路线的认证时钟是 **0.30 / 2**：

| 证据 | 内容 |
|---|---|
| `hybrid_model.py:149` | `clock_K_au: float = 0.3` |
| `主结果_完整参数与来源.md:114` | `clock_K_au / clock_n \| 0.3 a.u. / 2 \| selected_profile.json 认证链；不能使用 51 态构造器另一默认值 0.4/3` |
| `主结果_完整参数与来源.md:119` | `g1 = H(A1;1.2,6) × G(F1;0.4,4) × H(Int0;0.3,2)` |
| 本轮实测护栏 | 在**默认 0.30** 下逐字复现 `certified_v1=True`、19 窗、`1234567012345670123`、14/14/14、7/7/7、裕度 `1.1784609018563117` |

`K = 0.10` 是 HBY 那边 **HZZ 路线**的工作点（`diagnose_round3/4/5b: K_WORK = 0.10`），在 `FIGURE_STATUS.md:23` 里也正是以 HZZ 配置的身份出现（"600 h 验证属于保留时钟门、`clock_K=0.10`、负自馈 off 的另一个配置"）。

于是 §4 的

> 保留臂 | `clock = H(b0_I; 0.3, 2.0)`，`clock_K = 0.10`（认证工作点）

**同一格里写了两个互相矛盾的 `clock_K`**；§5 的"`0.3/2` + `K=0.10`（认证配置）"是同一处。

功能上不会崩：本轮扫描显示 HZH 在 `K ∈ [0.075, 0.60]` **全程认证**，所以取 0.10 也跑得过——但这正是危险之处：**图注会写下一个认证链从未用过的"认证值"，而且同一格两个数就是以后写出错图注的种子。**

**改法**：保留臂取 **0.30 / 2**，来源标 `主结果:114 / selected_profile.json`；若还想展示 0.10，就作为**第二条保留臂**单列，并注明"这是 HZZ 路线的工作点"。

## 5. 其余（低）

**D4 §5 的"同一个门在两种配置下符号相反"不成立。** 被删掉的因子在两边不是同一个门：

| | 模型 | act | repress | clock |
|---|---|---|---|---|
| fig5_bypass | HZZ 23 态 | `H(A1;1.2,4)` | `G(F1;0.4,4)` | `H(Int0;0.4,3)` |
| 新图 | HZH 34 态 | `H(A1;1.2,6)` | `1−H(F1;0.4,4)` | `H(Int0;0.3,2)` |

建议改成"**同一个门因子（第三因子）在两套末级上的作用相反**"，并把两句话各自留在自己的路线上。另外"门必需"这半边**目前还是推断**（你自己也写了"把…从推断变成实测"）——所以 §5 现在不能写成已成立的对照，只能写成"待测的预期"。

**D5 §1 问题 2 是跨路线引用。** `主结果:114` 的禁令属于 **HZH 路线**；在 HZZ 探索路线里 `0.40` 是**源文件值**，`fig5_bypass` 的 suptitle 自己就写着 *"clock_K left at its source value 0.40"*。所以 `fig5_bypass` 的毛病不是"用了被禁用的值"，而是"跑错了模型/路线"——建议降为问题 1 的推论。（提示：这正是你刚用 `FIGURE_STATUS:23` 警告过的那类混写。）

**D6 §4 的初态那一行缺一句限定。** round5b 的八个初态取自 **HZZ** 300 h 轨道。读窗谷时刻只由 `Int0` 决定、而 `Int0` 是两套共用前缀给的 ⇒ **时刻可以照搬**；但 HZH 是 34 态、末级 17 态不同 ⇒ **状态向量必须从 HZH 自己在 `clock_K=0.30` 的 300 h 轨道上取**，不能直接 `np.load` round5b 的 npz。建议写成："沿用 round5b 的八个读窗谷**时刻**，状态从 HZH 自身轨道取样"。

**D7 §2 的措辞。** "`hby_zmh_hby/` 全目录查 `clock|bypass|gate|ablat` → 无匹配脚本"字面不成立：`hby_zmh_hby/pdf_parameters/model_pdf.py:52` 含 `clock_K=self.tail.c.clock_K_au,clock_n=self.tail.c.clock_n`（参数上报行，不是消融）。结论（没有消融脚本）仍成立，建议改成"无消融/旁路脚本"并附这一条，免得别人重跑 grep 后把整条证据一起否掉。
