怎么用这份表

  1. 先看左边那张图——那就是这个组件长什么样。觉得「我这个内容放进去正合适」，就往下读。
    （折叠面板、标签页、轮播、弹窗这四张预览是可以点的，直接动手试试就知道手感了。）
  2. 再看「适合放什么」——里面每一条例句都直接对应到 wiki 的某个页面板块，照着对号入座。
  3. 最后看「注意」——这里写的都是容易踩的坑，尤其是无障碍和搜索引擎相关的，写之前扫一眼能省很多返工。
  4. 然后在文档里用文字描述你想要的效果，比如「这一段我想用折叠面板，三个问题各一条」，不用管技术怎么实现，那是网页组的活。

components/layout/ToC

长文章右边那条「本页目录」，让读者一眼看到这一页都讲了什么。

长什么样
一个浅灰底的方框，竖着列出本页所有小标题。读者往下滚的时候，当前读到的那一节会自动变成蓝底加粗高亮；三级小标题会比二级多缩进一格，层级一眼可辨。手机屏幕上它收成一条可以点开的长条，不占正文位置。
怎么操作
点任意一条就跳到对应的小节。
适合放什么
全站自动，由页面里的小标题自动生成，不需要手工维护。
注意
页面里用几个井号（## 表示二级、### 表示三级）写小标题，目录就会自动长出对应的条目。标题写得越清楚，目录越好用——它是读者快速扫读一整页的唯一入口，写「结果」不如写「荧光强度比对照组高 3.2 倍」。

Accordion 折叠面板

已启用

components/ui/Accordion

一排可以点开点收的条目，像手风琴一样。收起时只占一行，所以一页能塞下很多东西而不显得拥挤。

长什么样
每一行是一条浅灰底的横条，左边是标题文字，右边一个朝下的小三角。点一下，横条下面滑出内容区，三角翻转朝上。展开的内容区是白底，文字和标题左对齐在同一列。可以同时展开好几个，也可以设置成一组里只允许开一个。
怎么操作
点标题行展开或收起。键盘用户按 Tab 走到标题上、按回车同样可以开合。没有 JavaScript 的环境下会全部默认展开，内容不会丢。
适合放什么
  • FAQ 常见问题——读者只展开自己关心的那一条
  • 实验步骤——每一步折叠起来，读者按自己的进度逐步展开，不会一上来就被淹没
  • Safety 页的风险条目——逐条列出风险，展开看对应的应对措施
  • Parts 页的元件描述——一个元件一条，一页能放下十几个
注意
标题要写得能一眼看出里面是什么。读者决定要不要点开，全靠这一行标题——写「需要哪些质粒？」比只写「质粒」强得多。另外，如果这些内容读者一条都不能漏（比如安全规程），就不要折叠，老老实实全部铺开写。
占多大版面
收起时每条约 44 像素高，展开后按内容长短自动撑开。
技术说明（网页组看）

基于浏览器原生 <details> 元素，零 JavaScript，禁用 JS 也能用。多个面板设置同一个 groupName 可以实现「一组里同时只开一个」的手风琴效果。

Tabs 标签页

已启用

components/ui/Tabs

一排平行的标签，点哪个就显示哪块内容，同一块位置来回换。

长什么样
顶部横着一排文字标签，当前选中的那个下面有一条蓝色下划线，字加粗变蓝；其他的都是灰字。点另一个标签，下面的内容整块换掉，被选中的标签样式跟着挪过去。标签数量多到一行放不下的时候，这一排可以横向滑动。
怎么操作
鼠标点击切换；键盘用户按左右方向键在标签之间移动，按 Home 和 End 跳到第一个和最后一个。
适合放什么
  • Results 页——荧光数据 / 生长曲线 / 流式细胞，三种表征并列
  • Model 页——模型假设 / 参数取值 / 求解结果
  • Software 页——怎么安装 / 怎么用 / API 说明
  • 凡是「同一个主题下有几套平行内容，读者一般只关心其中一套」的情况，用它就比堆在一起清楚得多
注意
标签名要短，两到六个字最好，最长别超过一行宽度。还有一点很重要：标签页里藏起来的内容，在搜索引擎和直接读页面的人眼里是不存在的——如果几块内容同等重要，别藏在标签里，老老实实分段写出来。
占多大版面
标签条一行约 40 像素，内容区高度由最长的那块内容决定。
技术说明（网页组看）

完整的 ARIA Tabs 模式：role="tablist"、左右方向键导航、Home / End 跳首尾、roving tabindex。禁用 JS 时所有面板会依次铺开显示，内容不会丢失。

Card 卡片

已启用

components/ui/Card

一个个带边框的小方块，用来并列展示同类的东西。

长什么样
白底圆角方框，带一圈很浅的边框。里面可以放一张图（图片占满顶部通栏）、一个加粗标题、一段两三行以内的描述。鼠标移到卡片上，阴影会加深、整张卡微微上浮一点，表示它可以点击。另外还有一种「高亮变体」：左边多出一条橙色竖条、底色变成浅灰，用来强调某一张。
适合放什么
  • Team 页——每位成员一张，照片 + 姓名 + 分工
  • Partners / 合作方页——一排机构 Logo，各配一句介绍
  • 项目亮点——一页并列三四个核心贡献点
注意
卡片里的描述控制在一两句话，超过三行就该考虑改用折叠面板或者直接分段写。一排摆三到四张最舒服：少了浪费空间，多了每张太窄、字挤成一条。
占多大版面
一排三张时，每张约 280 像素宽、180 像素高。
技术说明（网页组看）

支持横向排列和纵向排列两种。窄屏时横向卡片自动改为纵向堆叠。链接放在标题里，整卡可点但只暴露一个链接，避免屏幕阅读器重复朗读。

Timeline 时间线

已启用

components/ui/Timeline

一条竖线串起一串圆点，按时间顺序讲故事。

长什么样
左侧一条竖直的灰线，线上每隔一段有一个实心圆点。每个圆点右边是这一条的内容：最上面一行是小号大写的日期（比如 2026-03），中间是加粗的标题，下面是一句描述。每一条还可以在标题旁挂一个彩色状态小标签（设计 / 构建 / 测试 / 学习 / 完成，各有各的颜色）。条目多了就一直往下延伸。
适合放什么
  • 项目推进——「几月做了什么」，按时间铺开
  • Human Practices——访谈和活动的先后顺序
  • Notebook——按天记录的实验日志
  • Engineering 页——DBTL 每一轮迭代
注意
它是纯展示组件，没有任何交互，也不需要读者点——所以只适合表达「先后顺序」的线性叙事。如果内容之间存在分支、循环或者互相依赖（比如「如果 A 成功就走 B，否则回到 C」），时间线表达不了，那种情况需要画流程图（见最后一节）。
占多大版面
每条约 90 像素高，十条左右就是一屏半。
技术说明（网页组看）

状态可选 design / build / test / learn / complete 五种，各配色都做过对比度校验。日期写成 2026-03 这种格式会被识别成机器可读时间。

QuoteCallout 引用块

已启用

components/ui/QuoteCallout

把一段话从正文里单独拎出来，让它跳出来被看见。

长什么样
左边一条橙色竖条，底色是浅灰，正文用斜体，下面跟着一行小字标出处（比如「— 受访者，某医院临床医生」）。如果出处是一个外部网站链接，后面会自动补一个小图标表示「会在新窗口打开」。
适合放什么
  • 引用文献——把一篇论文里的关键结论单独拎出来
  • 访谈原话——Human Practices 页引用受访者说的话，并标明来源
  • 合作方反馈——引用其他队伍或机构对你们的评价
  • 正文里任何「这句话想让读者记住」的地方，用它都比单纯加粗醒目
注意
一页别用太多，超过三四处就不显眼了。出处尽量写具体：谁说的、什么身份、什么时候。「业内人士表示」这种说法没有说服力，评审也不认。
占多大版面
三到四行，约 100 像素高。

DataTable 数据表

已启用

components/ui/DataTable

规规矩矩的表格，而且带排序功能。

长什么样
最上面一行是表头（灰底加粗），下面每行一条数据。行与行之间用浅灰色条纹隔开，方便横向读一长串数字而不会串行。写了排序功能的列，点一下表头就按那一列从小到大排，再点一下从大到小排，表头上会显示一个上下箭头表示当前方向。手机屏幕上表格自己内部左右滑动，不会把整个页面撑宽。
怎么操作
点表头排序，可以反复点来切换升降序。屏幕阅读器用户会听到「已按 XXX 升序排列」的语音播报。
适合放什么
  • Parts 页——元件清单：编号 / 名称 / 长度 / 状态
  • Measurement 页——测量数据和单位
  • Results 页——几组实验条件的横向对比
  • Contribution 页——和其他队伍方案的对比表
注意
只要有超过一列数字，就该考虑用表格，别写成一句话。评委读 Results 和 Measurement 的时候，要的是能横向对比的结构化数据，一段「A 是 3.2，B 是 4.1，C 是 2.8」的散文是读不下去的。另外每一列都要起个说清楚单位的名，写「长度 (bp)」而不是只写「长度」。
占多大版面
表头一行加每行约 36 像素。超过八行建议考虑拆分或者改用折叠。
技术说明（网页组看）

排序在前端完成：纯数字列按数值大小排（会先剥掉千分位逗号），其余按文本排并启用 numeric 比较。排序结果通过一个隐藏的播报区念给屏幕阅读器听。表头用 scope="col"，排序状态写在 aria-sort 上。

Badge 状态标签

已启用

components/ui/Badge

小小的彩色胶囊标签，贴在文字旁边表示状态或者分类。

长什么样
圆角小胶囊，里面是几个字的短文字。有六种颜色（深蓝 / 绿 / 黄 / 红 / 浅蓝 / 灰）和一种描边样式（透明底加彩色边框）。颜色本身带含义：绿色代表成功、黄色代表警告、红色代表失败。可以在文字前面加一个很小的图标，高度有三档可调。
适合放什么
  • Parts 页——每个元件的状态：已构建 / 待验证 / 失败
  • Team 页——在成员名字旁边标出分工
  • 任何列表里，给每一项打一个分类标签
注意
颜色不能是唯一的信息载体。红绿色盲在男性里大约每十二个人就有一个，他们分不出红和绿。所以标签上必须写字——不要做一个纯红色的圆点表示「失败」，要写「失败」两个字。这是无障碍的硬要求，评审也会看。
占多大版面
很小，一行可以并排放好几个。
技术说明（网页组看）

颜色不能作为唯一语义载体（WCAG 1.4.1）。支持做成可关闭的标签（带关闭按钮）。

ProgressBar 进度条

已启用

components/ui/ProgressBar

一条横条加一个百分比，一眼看出某件事做到几成了。

长什么样
一条横向的浅灰轨道，里面有一段蓝色的填充表示进度，右边跟着百分比数字。页面刚打开的时候，数字会从 0 快速滚到目标值（大约一秒钟），填充条同步展开。如果读者的系统设置了「减少动效」（一些对动画敏感的人会开这个开关），就直接显示最终值，不做动画。
适合放什么
  • 项目完成度——元件构建 82%、表征测试 45%，各环节推进到哪了
  • 构建进度——实验流程走到哪一步
  • Education 页——课程或活动目标的达成情况
注意
它适合表达「一个整体完成到几成」——也就是各部分的数字加起来有意义的情况。如果几个数字互不相干，并排的进度条会让人误以为它们能加总，那种情况改用数据表。

components/ui/ImageGallery

缩略图排成整齐的网格，点任意一张就全屏放大看细节。

长什么样
一堆缩略图排成整齐的网格，可以选每行 2 张、3 张或 4 张。点任意一张，整个屏幕变暗，那张图的大图浮在正中间，下面是图片说明，右下角标着「第几张 / 共几张」。每张缩略图下面还可以配一句说明文字。
怎么操作
点缩略图放大。放大状态下，可以用键盘左右方向键、点两侧的箭头，或者在手机上左右滑动来翻页；按 Esc 键或者点图片外面的暗处关闭。关闭之后，焦点会自动回到你刚才点的那张缩略图上。
适合放什么
  • 实验证据成套展示——凝胶电泳图、显微镜照片、流式图
  • Human Practices 照片墙——走访活动的记录
  • 只要读者需要「放大看细节」，用它就比在正文里直接插图强得多——正文里插满大图会把版面撑得极长，读者根本滚不到底
注意

六、关于画流程图

有队友问过——可以画，但需要先定一件事

结论是可以画。但 iGEM 有一条硬性规定：所有资源必须自托管，不能引用外部网站。 这意味着不能像平时那样贴一个在线画图服务的链接，也排除掉了几种常见做法。

目前比较现实的几个方向：

Mermaid 代码写图 推荐

用一段类似代码的简单文字描述图的连接关系，构建网页时自动转成矢量图。好处是改一个字就改一处，不用重画；坏处是样式比较朴素、不能自由摆放位置，而且需要先给项目加一个转换插件。

设计组画好导出 SVG

在设计软件（Figma、draw.io 之类）里画好，导出成矢量图文件交给网页组。好处是样式自由、好看；坏处是每次改动都要重新画一遍再重新导出。适合少数几张最重要的图，比如电路图和 DBTL 循环。

在动手之前需要先定一件事：你们写的文档要怎么变成网页。 目前站点的所有页面都是网页组手工写的，没有任何「把文档自动转成页面」的流程。 Mermaid 这种写法必须先把这个流程配上，否则你们按它的语法写完，到网页上只会显示成一段普通文字。 这件事需要你们和网页组碰一下再决定。

这份图鉴由本地代码生成，每个组件的描述都对照源码核对过，配色与实际 wiki 一致，所以预览的观感和真实效果基本相符。

预览是简化还原，用来判断「长什么样」足够了。具体一个组件最终在你那页里呈现成什么样子， 还要等页面真正接上、配合全局样式微调之后才定——所有组件目前都还是候选状态，页面里的用法也都只是占位示例， 完全可以按内容需要重新安排。
